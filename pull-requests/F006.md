# Preserve explicit masses when exporting SimState to ASE

<!-- Local review draft. Do not publish until the PDF and evidence package have been reviewed and the evidence repository is public. -->

## Problem and result

`state_to_atoms` constructs ASE atoms without passing `state.masses`. ASE therefore supplies default elemental masses, losing explicit isotope or custom masses that `atoms_to_state` imported correctly. A hydrogen pair with masses `[2.014, 3.016]` returns `[1.008, 1.008]` after export.

This passes each system's explicit masses to the ASE constructor after converting the mass tensor to a CPU NumPy array alongside positions. The regression checks a single system and a batch containing systems of different sizes and custom masses, then imports the exported ASE atoms again to verify mass preservation.

## Reproduction

```sh
python -m pytest -q tests/test_io.py -k preserves_custom_masses
```

Both new cases fail at the expected mass assertion before the fix and pass afterward. The tests use the native ASE conversion API on CPU float64.

## Scope and evidence

The change is limited to the ASE exporter and its custom-mass regression. It does not extend the finding to other conversion formats or establish isotope-dependent dynamics behavior.

The [F006 evidence and native ASE control](https://github.com/Brean0/torchsim-validation/blob/main/docs/findings/F006.md) documents the original conversion invariant failure. The evidence repository is private while this draft is under review; make that link accessible before publication.
