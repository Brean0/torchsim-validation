## Problem and result

With the default full neighbor list, `PairForcesModel` applies each directed pair force to both endpoints. Because the reverse entry is also present, a symmetric interaction is counted twice. Two isolated soft-sphere atoms at distance 0.5, with epsilon=sigma=1 and alpha=2, return x forces `[-1, 1]` instead of `[-0.5, 0.5]`.

Accumulate each full-list entry on its source atom, and update both endpoints only for a half list. This follows the existing `PairPotentialModel` accumulation pattern and also handles asymmetric force functions. The regression includes an asymmetric case with source force magnitudes 1 and 2; its expected x forces are `[-1, 2]`, so dividing the old result by two would not satisfy it.

## Reproduction

```sh
python -m pytest -q tests/models/test_pair_potential.py -k 'isolated_pair_direct_forces or preserve_asymmetric'
```

Before the fix, the new tests produce 4 failures and 2 passing half-list controls. After the fix, all 6 cases pass. The tests exercise `torch_nl_n2` and the default `torchsim_nl` backend on CPU float64.

## Scope and evidence

This change is limited to direct-force accumulation, its explanatory docstring, and regressions. It does not change per-atom energy weighting, stress accumulation, neighbor-list construction, or cutoff behavior. GPU and long-running simulation validation were not performed.

The [F001 evidence and native reference comparison](https://github.com/Brean0/torchsim-validation/blob/main/docs/findings/F001.md) documents the original discrepancy and its ASE, LAMMPS, JAX MD, and TorchMD controls.
