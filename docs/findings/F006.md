# F006 — ASE export loses explicit custom masses

**Evidence level:** measured conversion invariant failure, with native mass-preserving ASE trajectory IO as a control. TorchSim audited commit, ASE 3.29.0, CPU float64.

The test creates ASE H2 with explicit masses **[2.014,2.014] amu**, positions [[0,0,0],[1,0,0]], 10 Å cubic cell and periodic boundaries. `torch_sim.io.atoms_to_state` preserves the input masses in `state.masses`. Exporting with `torch_sim.io.state_to_atoms` returns **[1.008,1.008] amu**, equal to ASE's default masses for elemental H. The export loses the explicit isotope/custom-mass information.

The independent native IO control writes the original ASE atoms to a temporary ASE trajectory and reads it back using native `ase.io.write/read` with format `traj`. It preserves **[2.014,2.014]**. The temporary trajectory is not vendored into this repository. This checks data preservation; it does not simulate force-field or isotope physics.

| Conversion stage or control | Recorded masses (amu) | Explicit input masses preserved |
|---|---|---|
| Input ASE atoms | [2.014, 2.014] | Input baseline |
| Imported TorchSim state | [2.014, 2.014] | Yes |
| Exported ASE atoms | [1.008, 1.008] | No; equal to ASE's default H masses |
| Native ASE trajectory write/read round trip | [2.014, 2.014] | Yes |

[TorchSim `state_to_atoms`, lines 39–128](https://github.com/TorchSim/torch-sim/blob/d6d8e9fc30129e01a05b551c2d71912821c9b68b/torch_sim/io.py#L39-L128) constructs `ase.Atoms` from symbols, positions, cell and PBC without providing `state.masses`. The native mass-preserving control is [ASE 3.29.0 trajectory IO](https://gitlab.com/ase/ase/-/blob/3.29.0/ase/io/trajectory.py): `write_atoms` writes explicit masses and `read_atoms` passes them back to the Atoms constructor. The finding applies to the tested ASE conversion route. Other exporters are outside its scope.

## Recommended change (proposed)

In `state_to_atoms` at `torch_sim/io.py`, audited lines 73–75 and 100–102, convert `state.masses` to a CPU NumPy array alongside positions. Pass the current system's masked masses to the ASE constructor:

```python
masses = state.masses.detach().cpu().numpy()
# In the per-system Atoms constructor:
# masses=masses[mask]
```

The submitted patch implements this change and adds a native ASE round-trip regression for a single state and a batch with different system sizes and explicit custom masses. Its regression fails on the audited code because ASE supplies default elemental masses. The patch is a separate proposal; it does not alter the audited source or the saved measurements. The change is limited to the ASE exporter. It makes no claim about custom-mass handling in other exporters or isotope dynamics.
