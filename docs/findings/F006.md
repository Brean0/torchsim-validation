# F006 — ASE export loses explicit custom masses

**Evidence level:** measured conversion invariant failure, with native mass-preserving ASE trajectory IO as a control. TorchSim audited commit, ASE 3.29.0, CPU float64.

Create ASE H2 with explicit masses **[2.014,2.014] amu**, positions [[0,0,0],[1,0,0]], 10 Å cubic cell and periodic boundaries. `torch_sim.io.atoms_to_state` preserves the input masses in `state.masses`. Exporting with `torch_sim.io.state_to_atoms` returns **[1.008,1.008] amu**, equal to ASE's default masses for elemental H. The explicit isotope/custom-mass information has been lost.

As an independent native IO control, write the original ASE atoms to a temporary ASE trajectory and read it back using native `ase.io.write/read` with format `traj`. It preserves **[2.014,2.014]**. The trajectory is temporary and is not vendored into this repository. The comparison is a data-preservation invariant, not a force-field or isotope-physics simulation.

[TorchSim `state_to_atoms`, lines 39–128](https://github.com/TorchSim/torch-sim/blob/d6d8e9fc30129e01a05b551c2d71912821c9b68b/torch_sim/io.py#L39-L128) constructs `ase.Atoms` from symbols, positions, cell and PBC without providing `state.masses`. The native mass-preserving control is [ASE 3.29.0 trajectory IO](https://gitlab.com/ase/ase/-/blob/3.29.0/ase/io/trajectory.py): `write_atoms` writes explicit masses and `read_atoms` passes them back to the Atoms constructor. This is bounded to the tested ASE conversion route; it does not assert all exporters lose masses.
