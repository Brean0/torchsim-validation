# F002 — Per-atom energies do not sum to the returned system energy

**Evidence level:** measured internal invariant failure, with a native ASE control. CPU float64, TorchSim commit `d6d8e9fc30129e01a05b551c2d71912821c9b68b`, ASE 3.29.0. The two model classes reproduce the same generic accumulation issue, so they count as one finding.

The original two-atom soft-sphere case has distance 0.5, sigma=epsilon=1 and alpha=2. TorchSim returns system energy **0.125** and atom energies **[0.125, 0.125]**, whose sum is **0.25**. Both atoms receive the complete unique-pair energy instead of half.

The live native comparison uses two nonperiodic Ar atoms separated by 1.3 Å, Lennard-Jones epsilon=1 eV, sigma=1 Å and cutoff=2.5 Å. Results in eV:

| Quantity | TorchSim | Native ASE |
|---|---:|---:|
| Returned system energy | -0.6570169144600471 | -0.6407000233240471 |
| First atom energy | -0.6570169144600471 | -0.32035001166202354 |
| Second atom energy | -0.6570169144600471 | -0.32035001166202354 |
| Sum / system energy | 2 | 1 |

ASE's `LennardJones` calculator shifts the energy at its cutoff, so the comparison uses each engine's own sum-of-atom-energies invariant rather than equating absolute energies across engines. The native calls are `Atoms.get_potential_energies()` and `Atoms.get_potential_energy()` on the same ASE calculation.

The relevant TorchSim code is [`PairPotentialModel.forward`, lines 405–418](https://github.com/TorchSim/torch-sim/blob/d6d8e9fc30129e01a05b551c2d71912821c9b68b/torch_sim/models/pair_potential.py#L405-L418). System energy receives one weighted pair contribution, while the atom output receives that contribution at both endpoints. The native control is [ASE 3.29.0 `LennardJones.calculate`](https://gitlab.com/ase/ase/-/blob/3.29.0/ase/calculators/lj.py). The JSON evidence records checksums for the installed source.
