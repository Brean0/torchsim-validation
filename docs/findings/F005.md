# F005 — Unequal-mass initialization uses a different zero-momentum projection

**Evidence level: qualified convention/distribution finding.** TorchSim and native JAX MD share one rule; native ASE `Stationary(preserve_temperature=False)` uses another. Both rules remove total momentum and center-of-mass velocity. This evidence does **not** establish a failure to remove COM motion or unanimous cross-library disagreement.

For raw Gaussian momenta p, total P, particle masses m_i and total mass M:

- TorchSim subtracts **P/N** from each particle's momentum.
- ASE subtracts **m_i P/M**, applying one common velocity shift.

Use masses **[1,4]**, kT=1, Torch generator seed=4, and reconstruct the identical raw Gaussian momenta with a separate generator at the same seed. Pass that raw sample to native ASE, with temperature preservation disabled so no extra rescaling obscures the comparison. The maximum momentum difference is **0.7901322663896455**. Both returned total momenta are [0,2.22e-16,0]. The native ASE result matches the common-velocity formula with **zero maximum error**.

If the intended distribution is canonical Gaussian momenta conditioned on total momentum zero, the conditional covariance in one coordinate is `diag(m_i*kT) - kT*m*m.T/M`. The common-velocity projection produces that covariance. For this two-particle case, each particle's conditional momentum variance is **0.8**. The arithmetic-mean-momentum projection instead gives variance **(1+4)/4=1.25** for both particles. A live TorchSim calculation over **32,768 independent systems**, three coordinates each, seed=71, measures **1.2510351317695345** and **1.2510351317695347**, consistent with its implemented projection. The distribution concern therefore depends on the intended constrained thermal distribution; simple total-momentum removal alone does not select one rule.

The independent native JAX MD 0.2.29 reference reconstructs that engine's own raw Gaussian draw using its actual subkey path, then calls public `simulate.initialize_momenta`. It matches arithmetic-mean subtraction with **0 maximum error**; the difference from the ASE-style rule is **1.0025395541989457**. Random sequences are not equated across engines. This is an explicit counterexample to treating ASE's choice as unanimous independent proof of a TorchSim bug.
