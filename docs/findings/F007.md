# F007 — List initialization ignores requested dtype

**Evidence level:** measured API consistency failure. **Not an external physics comparison.** CPU device behavior is a control; accelerator transfer has not been executed in this evidence.

| Input form | Input dtype | Requested dtype | Returned dtype | Requested device | Returned device |
|---|---|---|---|---|---|
| Single `SimState` | `torch.float32` | `torch.float64` | `torch.float64` | `cpu` | `cpu` |
| List of two `SimState` objects | `torch.float32` | `torch.float64` | **`torch.float32`** | `cpu` | `cpu` |

The test initializes a two-atom float32 `SimState` and calls `initialize_state` with `device=cpu` and `dtype=float64`, first on that state and then on a list containing it twice. The single-state call returns **torch.float64**; the list call returns **torch.float32**. Both return CPU tensors. The same public dtype argument is honored for the single-state input and ignored for the list input.

[The audited `initialize_state`, lines 1554–1610](https://github.com/TorchSim/torch-sim/blob/d6d8e9fc30129e01a05b551c2d71912821c9b68b/torch_sim/state.py#L1554-L1610) clones and calls `.to(device, dtype)` in its single-SimState branch. The list-of-SimStates branch returns `concatenate_states(system)` directly. The source also indicates that this branch bypasses device conversion. The executed reproduction establishes the dtype discrepancy. A CPU-to-GPU failure has not been measured in this CPU-only run.

The reference check is consistency between two documented input forms to the same TorchSim initializer. This finding does not claim an equivalent ASE/JAX MD/LAMMPS/TorchMD API comparison.
