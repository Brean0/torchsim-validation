# F004 — A vector timestep broadcasts over coordinates rather than systems

**Evidence level:** measured batched-integrator discrepancy, with native ASE `VelocityVerlet` runs and scalar-timestep controls. CPU float64.

The documented API accepts `dt` shaped `[n_systems]`. Initialize three systems with two particles per system, all positions zero, masses=1, momenta=[1,1,1] per particle and forces zero. Set **dt=[0.1,0.2,0.3]**. After one step, every coordinate within system s should move by dt[s].

TorchSim instead returns **[0.1,0.2,0.3] for every particle**, independently of system membership. Independent native ASE `IdealGas` + `VelocityVerlet` runs return [0.1,0.1,0.1] for both particles of the first system, [0.2,0.2,0.2] for the second, and [0.3,0.3,0.3] for the third. The maximum position error is **0.19999999999999998**. Repeating TorchSim with scalar dt values 0.1, 0.2 and 0.3 gives maximum errors **[0,0,0]** against uniform scalar displacements.

This tests the free-particle equation dr=v*dt in consistent internal units. ASE's timestep uses its internal time unit, and velocity is set to one Å per internal time unit. The script keeps the physical time scales consistent; it does **not** pass femtoseconds as internal time. The zero-force native calculator is [ASE 3.29.0 `IdealGas`](https://gitlab.com/ase/ase/-/blob/3.29.0/ase/calculators/idealgas.py), and the independent integrator is [ASE 3.29.0 `VelocityVerlet.step`](https://gitlab.com/ase/ase/-/blob/3.29.0/ase/md/verlet.py).

[TorchSim `momentum_step` and `position_step`, lines 167–209](https://github.com/TorchSim/torch-sim/blob/d6d8e9fc30129e01a05b551c2d71912821c9b68b/torch_sim/integrators/md.py#L167-L209) multiply `[n_atoms,3]` tensors directly by `[n_systems]`, without indexing dt by `system_idx` and adding a coordinate axis. With exactly three systems, broadcasting silently treats the dt entries as x/y/z components. The complete [NVE step](https://github.com/TorchSim/torch-sim/blob/d6d8e9fc30129e01a05b551c2d71912821c9b68b/torch_sim/integrators/nve.py#L74-L138) uses these operations. This reproduction isolates position propagation with zero forces. It leaves thermostat behavior untested and does not establish that all scalar integrator use is wrong.
